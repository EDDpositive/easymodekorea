# easymodekorea.com 혹평 리뷰 (1차, 2026-11-20)

방법: 라이브 사이트를 내장 브라우저로 데스크톱·모바일(375px) 폭에서 확인, `src/build.py`·`src/data.py`·`src/vi.py`·`hosts.html` 코드 확인, 핵심 사실 5건을 공식 발표·언론 보도와 대조.

## 한 줄 결론

빠르고 깔끔하며 "내 상황별 답"이라는 콘셉트는 경쟁 사이트에 없는 강점입니다. 하지만 **가이드 본문이 너무 얇아서**(택시 가이드 본문 약 88단어, 페이지 전체 약 237단어) 검색 1페이지에 오른 1,500~3,000단어짜리 스크린샷 가이드와 경쟁이 안 됩니다. 사실 오류도 2건 있습니다(1339 안내, 전자도착카드를 "보도에 따르면"으로 흐리게 쓴 부분). 지금 상태는 "잘 만든 요약 카드"이지 "검색 1위 가이드"가 아닙니다.

| 가이드마다 "올해 바뀐 내용"(변경 기록에서 해당 가이드 것만), 답 상자에 "확인 방법" 링크, 홈에 "가이드 21개, 마지막 확인일, 올해 변경 11건" 한 줄 | 날짜·출처·변경 이력은 확인해서 적어야 하는 것. 변경 전에 쓰인 글과 학습된 답은 옛 규칙일 수 있음(사실 그대로, AI가 틀렸다는 사례를 지어내지 않음) |
| 갈 곳 목록(내 여행): 한국어 주소·장소 이름·구글 지도 링크를 넣으면 기사에게 보여 주기, 네이버 지도·카카오맵 열기가 한 번 탭 | 택시 앞에서는 입력할 틈이 없음. 저장해 둔 것을 탭 한 번으로 |
| 숙소 주소가 있으면 홈 맨 위에 "기사에게 보여 주기" 버튼 | 앱을 열고 탭 한 번 |
| 식사 제한·알레르기 카드 12개, 결제가 안 될 때 카드 7개 | 카운터에서 바로 보여 주는 큰 글씨, 오프라인 |
| 가이드에서 내 상황 바로 고르기(한 번 고르면 모든 가이드가 그 기준) | 매번 상황을 설명할 필요가 없음 |
| `llms.txt`(가이드별 답과 확인일, 변경 기록, 인용 방법)와 `llms-full.txt`(전체 본문·출처)를 빌드가 생성, 구조화 데이터에 확인일(`lastReviewed`)과 출처(`citation`) | AI 검색이 이 사이트를 출처로 쓰기 쉽게 |

만들지 않은 것과 이유
- 일반 여행 체크리스트를 앞으로 꺼내기, 환율 계산기, 키오스크 단어 번역, 일정 짜기, 예절 안내: 챗봇이나 번역 앱이 이미 잘함.
- 결제가 막힐 때의 전체 가이드(선불카드 선택 등): 값어치는 크지만 사실 확인과 출처가 필요한 새 글이라 다음 내용 라운드로. 이번에는 사실이 필요 없는 문장 카드만.
- 명절 휴무·막차 같은 날짜별 주의: 해마다 확인해야 하는 자료가 필요. 범위를 "설·추석 연휴 날짜 표 1개, 매년 12월 갱신"으로 잡으면 가능.
- 일행과 공유: 값어치가 상대적으로 낮아 뒤로.
- 수익: 지금은 만들지 않음. AI와 겹치지 않는 후보는 오프라인 팩 정도. 제휴 링크를 넣으면 "어떤 앱도 돈을 내고 실리지 않는다"는 지금 문구와 충돌하므로 넣기 전에 문구와 표시 원칙부터 정해야 함.

### 증거를 보고 계획에서 바꾼 것

- 카드 브랜드·발급국을 묻지 않음. 브랜드별 가맹 여부는 출처로 확인되는 사실이 없음. 대신 결제 방식(실물 카드, 폰 지갑만, 현금 위주)을 물음.
- 아이·이동 약자 질문은 뺌. 확인된 내용이 없어 답을 지어내게 됨.
- 점수는 "출발 전에 할 수 있는 일"만 셈. 도착 후 단계는 목록에 보이되 점수에는 넣지 않음(출발 전에 다 채울 수 있어야 하므로).
- 별도 시작 화면을 없애고 첫 질문을 바로 보여 줌(탭 한 번 줄임). "7번 탭"이라는 문구는 질문 수가 폰에 따라 6~7개라 "1분"으로 바꿈.
- 택시 앱에 카드를 집에서 미리 등록하라는 단계를 추가(k.ride 리뷰에서 "카드 등록 전에는 호출 검색이 안 됨"). 리뷰가 출처임을 문장에 밝힘.
- 카드 거절 화면에 두 줄 추가: 2026-03부터 서울 지하철 신형 기기가 해외 카드를 받음(중앙데일리), WOWPASS는 교통 잔액이 결제 잔액과 따로임.

### 규칙 (모든 화면, 5개 언어)

1. 한 항목은 한 줄. 문장보다 라벨. 아이콘으로 뜻이 전해지면 글을 뺌.
2. 설명, 근거, 예외는 탭 뒤("+"로 펼침)에 둠. 첫 화면에는 답과 할 일만 둠.
3. 날짜 있는 확인된 사실은 지우지 않고 짧게 씀. ✓ 날짜는 줄에 남기고, 출처 이름은 링크("출처")나 펼친 안쪽에 둠.
4. 제목 밑 소개 문장, 화면이 이미 보여 주는 것을 다시 설명하는 안내 문장은 넣지 않음.
5. 한도(영어, 375×812, 닫힌 접기 제외). 넘으면 다른 글을 빼거나 접음.

| 화면 종류 | 첫 화면 단어 | 첫 화면 긴 줄 | 페이지 전체 단어 |
|---|---|---|---|
| 도구 화면: 홈, Ready 결과, 내 여행, 도움 | 70 이하 | 3 이하 | 300 이하 |
| 답 화면: 가이드, 문제 상황 5개 | 120 이하 | 6 이하 | 330 이하 |
| 한국어 카드 목록 | 70 이하 | 3 이하 | (목록이라 없음) |

`tools/browser_check.py`가 매번 이 한도를 검사하고, `python tools/text_density.py`로 언어별 숫자를 볼 수 있음.

### 바꾼 것

- 홈: 제목 밑 소개, 상황 카드의 설명 줄(검색어로는 남김), 첫 질문 밑 "왜 묻는지", 오프라인 안내 줄을 뺌. 신뢰 줄은 "21 guides · checked 20 Nov 2026".
- 가이드: 설정 이름을 되풀이하던 답 제목은 화면 읽기용으로만 남김. "도구 열기" 버튼과 숙소 운영자 안내 줄을 뺌. 사실 줄마다 날짜가 있어 확인 줄은 "출처 · 확인 방법"만 남김. 단계는 첫 문장만 보이고 나머지는 "+".
- 문제 상황 5개: 단계마다 첫 문장과 ✓ 날짜만 보이고, 나머지 설명과 출처는 "+" 안. 소개 문장과 "순서대로" 제목은 화면에서 뺌.
- Ready: 소개 문단을 빼고, 앱별 줄은 모두 접힌 채 시작(색 표시가 먼저 알려 줌). 출발 전 할 일 20줄을 한 줄씩으로 다시 씀. 순서는 그대로라 이미 체크한 칸이 유지됨. "확인 필요" 안내도 짧게.
- 내 여행·도움: 공유 설명 두 문장을 "🔒 Nothing uploaded: the list is in the link" 한 줄로 줄이고, 날짜 안내와 오프라인 안내 줄을 뺌. 주소 안내는 "🔒 Only on this phone".
- 앱 화면(한국어 카드, 내 여행, 도움, 개인정보, Ready): 제목 밑 소개 문장을 뺌.
- 함께 고침: 가이드 위 공유 버튼이 흰 바탕에 흰 아이콘이라 보이지 않았음(24차에서 만든 내 여행 공유 칸의 `.share` 스타일과 이름이 겹침). 버튼이 보이는지 검사를 추가함.

### 숫자 (영어: 첫 화면 단어 / 긴 줄 / 전체 단어)

| 홈 | 101 / 5 / 318 | 62 / 1 / 182 |
| 가이드: 택시 | 117 / 5 / 366 | 110 / 6 / 280 |
| 가이드: 공항 | 125 / 6 / 387 | 111 / 6 / 294 |
| Ready 결과 | 111 / 4 / 505 | 54 / 0 / 258 |

- 일본어도 같은 방향: 홈 115→73, Ready 143→74, 카드 거절 138→105, 내 여행 91→52.
- 가이드 첫 화면은 조금만 줄었음. 첫 화면 대부분이 답(판정, 날짜 있는 사실 2~3줄)이기 때문. 단계가 짧아져 첫 화면에 단계가 하나 더 들어오면서 긴 줄 수는 5에서 6이 됨.

### 남은 것

- 가이드 판정 문장(가이드 21개 × 설정 3개 × 5개 언어)과 단계 원문은 손대지 않음. 다음에 줄일 후보.
- 줄인 문구는 원어민 확인 전(`docs/translation-review.md`에 추가).

검증: `tools/check_site.py` 17항목, `tools/browser_check.py` 38항목 통과. 375px 폭에서 밝은·어두운 화면, 영어·일본어·베트남어로 확인. 스토어 스크린샷 5장을 새로 만듦.
